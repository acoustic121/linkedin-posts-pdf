Every developer has typed git push --force at 2 AM and immediately regretted it.
(with real examples you can use right now)

1. Git Clone
 ↳ What: Downloads a complete copy of a repository from GitHub to your computer.
 ↳ Command/Tool: git clone https://github.com/username/repo.git
 Use Case: When your team lead tells you to grab the project code and start working.

2. Git Status
 ↳ What: Shows you which files you have changed, added, or deleted.
 ↳ Command/Tool: git status
 Use Case: When you have been coding for an hour and want to see what a mess you made.

3. Git Add
 ↳ What: Tells Git which specific changed files you want to save next.
 ↳ Command/Tool: git add .
 Use Case: When you are ready to package your latest bug fixes together.

4. Git Commit
 ↳ What: Saves your added changes permanently into Git history with a helpful note.
 ↳ Command/Tool: git commit -m "fix login button bug"
 Use Case: When you want to leave a sticky note for your team about what you just did.

5. Git Push
 ↳ What: Uploads your saved local commits up to GitHub so everyone else can see them.
 ↳ Command/Tool: git push origin main
 Use Case: When you finish your task and want to share your code with the team.

6. Git Pull
 ↳ What: Downloads and merges the latest code changes made by your teammates.
 ↳ Command/Tool: git pull
 Use Case: When your coworker tells you "I fixed the database, get my latest changes."

7. Git Checkout
 ↳ What: Switches you over to a different branch so you do not mess up the main code.
 ↳ Command/Tool: git checkout -b feature-login
 Use Case: When you are starting a brand new feature and need your own sandbox.

The best way to learn? Open a terminal and try these yourself.

My advice:
 ↳ Always run git status before you type git add so you know what files are moving.
 ↳ Never run git push --force on the main branch unless your senior engineer tells you to.
