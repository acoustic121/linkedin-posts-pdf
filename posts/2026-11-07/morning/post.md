Every time you click around the Azure portal to build servers, you waste precious hours doing it all over again.
(with real examples you can use right now)

1. Provider Configuration
 ↳ What: Tells Terraform to talk to Microsoft Azure using your credentials.
 ↳ Command/Tool: terraform init
 Use Case: When your boss asks you to set up a brand new cloud project in minutes.

2. Resource Group
 ↳ What: A neat digital folder that holds all your cloud toys together.
 ↳ Command/Tool: az group create
 Use Case: When you want to delete an entire app test environment with just one click.

3. Virtual Network (VNet)
 ↳ What: Your private digital highway where your servers safely talk to each other.
 ↳ Command/Tool: terraform validate
 Use Case: When you need to isolate your database from the public internet.

4. Subnet
 ↳ What: Lanes on your digital highway to separate web servers from databases.
 ↳ Command/Tool: terraform plan
 Use Case: When you want to see what will be built before spending actual money.

5. Network Security Group (NSG)
 ↳ What: A digital security guard that decides who gets to enter your servers.
 ↳ Command/Tool: terraform apply
 Use Case: When you need to block all random internet traffic except port 80 for your website.

6. Virtual Machine (VM)
 ↳ What: A powerful computer running in the cloud waiting for your code.
 ↳ Command/Tool: terraform destroy
 Use Case: When you want to clean up your playground at the end of the day so you don't get billed.

The best way to learn? Open a terminal and try these yourself.

My advice:
 ↳ Always run a plan before applying your changes to avoid nasty surprises.
 ↳ Never push your cloud passwords or secrets directly into your GitHub code.
